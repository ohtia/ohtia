# STORY-003-010 — Conversation view

## Description

Show one conversation in the chat panel with attributed plain-text messages, streamed replies, reading-position rules, paging by 50, panel states and the shared timeline contract. Carry the research operations through the application port, with the research subscription and text parts for texts longer than one port string. Markdown rendering, "Copy message" and links are STORY-003-011; the composer is STORY-003-012 and notices are STORY-003-013.

## Acceptance criteria

- [ ] Hostile content (`<script>`, HTML and `javascript:` addresses in message text) shows as plain text and never inserts HTML or violates the packaged CSP.
- [ ] A long reply while reading above the end does not move the view, and the round "Jump to latest message" button with `arrow-down` appears centered above the composer.
- [ ] A streaming reply shows "{agent} is writing…" with `pen-line` and no actions; every saved message shows its actions row without hover; researcher messages are end-aligned bubbles on `surface.emphasis`.
- [ ] Each panel state shows its text, and a failed earlier page shows its notice with "Load earlier messages" below it.
- [ ] A `conversation.rename` through the port that another rename preceded returns `stale_revision` with the conversation's `revision`, and `docs/application-port.md` states that for a research operation it means reading the named record again.
- [ ] A missing sequence number makes the window request the full text.
- [ ] A `conversation.read` of 128 conversations whose items exceed the result bound returns the whole items that fit, in the order requested, and the identifiers left, which the window reads again.
- [ ] A 120-item conversation loads its latest 50 and then 50 more each time "Load earlier messages" is used, without moving the reader; scrolling to the top loads nothing; the button disappears once the first item is loaded; and a page that ends inside a position, such as between a reply and its card, loses and repeats no item.
- [ ] After a sequence gap the window subscribes again and rereads what it shows.
- [ ] A window with no open project holds the research subscription and receives the events of the records shared by every project.
- [ ] Each research rejection returns its code with its next action, and a research read held by a slow data service past `request_deadline_ms` ends with `timeout`.
- [ ] `docs/application-port.md` defers the research error codes to `errorActions` and `operationErrorCodes` with the exact paragraph of SPEC-003-015, so later stories change no list in it.

- [ ] With the researcher's account, a real reply streams into the panel.
