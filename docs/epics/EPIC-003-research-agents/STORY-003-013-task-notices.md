# STORY-003-013 — Task notices

## Description

Give each task state and failure reason from STORY-003-005 to STORY-003-009 its notice in the conversation, with "Resume {service} requests ({n})", "Continue all ({n})", "Try again", "Start reply again" and the destination-line variants. Every text takes `{service}` from the task's connection and, where the meaning depends on how the service charges, the variant of its kind of connection.

## Acceptance criteria

- [ ] Each state and failure reason shows its exact notice text, including "Stopped before it was sent." for a task stopped before dispatch, "{service} doesn't allow this account to use its plan in Ohtia. Sign out in Settings › Connections, then choose “Sign in with another account”, or connect another service." for `not_eligible` on ChatGPT, "{agent} sent an empty reply." for `empty_reply`, and no notice for a task cancelled by coalescing; with a fake API-key connection, every `api_key` variant shows.
- [ ] No notice names a fixed service.
- [ ] A failed task that saved no text shows its notice at its reserved reply position, above the researcher messages written while it ran.
- [ ] Double clicks on "Resume {service} requests ({n})", "Continue all ({n})", "Try again" or "Start reply again" create no extra tasks, and each `{n}` counts paused tasks of other projects too and changes when tasks of another project are blocked, resumed, coalesced or stopped; after a sequence gap the window reads `pause.read` again.
- [ ] At the pending limit, "Try again" and "Start reply again" show "Too many replies are waiting. Nothing was started; try again when some finish."; a failed and an unconfirmed result of each of the four buttons show their notices, and repeating an unconfirmed one creates no extra task; "Resume {service} requests ({n})" and "Continue all ({n})" pressed in a second window after the first window already ran them succeed without change, and the second window reads `pause.read` again.
- [ ] "Try again" appears only on the latest reply task, leaves a partial reply of the failed task out of the new task's input, and is rejected when a newer task exists, showing "A newer reply already answers these messages."; after a failure for an empty model list it sends `model_list_refresh` and its new task waits queued for main's report; "Start reply again" likewise appears only on the latest reply task and shows the same notice when rejected.
- [ ] `task.tryAgain`, `pause.read`, `usagePause.resume`, `task.startAgain` and `task.continueAll` reach the data service through the application port.
- [ ] "Check usage" opens `https://chatgpt.com/settings/usage` in the system browser.
- [ ] With the researcher's account, a disconnected ChatGPT keeps the message waiting and reconnecting gets the reply.
- [ ] A notice right below its agent's text shows no `VoiceLabel`; status notices use `surface.emphasis` with a `border.subtle` border; a stopped task with saved text shows only "Incomplete — stopped by you" with its usage line; only the latest reply failed with `usage_limit_reached` shows "Resume {service} requests ({n})" and "Try again", and an earlier one shows its notice without buttons.
- [ ] With the researcher's account, a cut network leaves the task uncertain, or failed with `inactivity_timeout` when the connection reports nothing, and "Start reply again" or "Try again" answers it.
- [ ] The V16 scenario of `workspace-layout.md` passes for notices: stopping before a provider identity exists, partial output, a reply that fails after its message was saved, and unknown outcomes.
- [ ] Every notice's buttons and links sit below its box, never inside it, and an `invalid_output` cut shows "Incomplete — Ohtia couldn't read the rest of the reply".
