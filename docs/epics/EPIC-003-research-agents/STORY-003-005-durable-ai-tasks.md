# STORY-003-005 — Durable AI tasks

## Description

Add `tasks`, `attempts` and `messages.task_id`, the multitask queue with the general limit of 10 and ChatGPT's declared 3, one running and one not-started task per conversation, reserved reply positions, coalescing, the shared input rule and the input, output, work and pending limits, single session renewal, failure codes, the second attempt after a refused permit, the uncertain quarantine and the development project. Write the new ADR that replaces every part of ADR-0011 and ADR-0037 this EPIC changes.

## Acceptance criteria

- [ ] With the researcher's account, three conversations run at once and a fourth waits.
- [ ] Two messages sent while a reply streams produce one reply that sees the previous one.
- [ ] With the fake provider, one renewal with three running tasks happens once and no task loses its session.
- [ ] Each documented OpenAI error maps to its outcome code.
- [ ] An uncertain task holds its slot while the others continue.
- [ ] A message sent while a reply runs takes a position after the reply's reserved one and appears below the reply; a task that ends without text leaves its reservation unused.
- [ ] A provider result that completes without any text fails with `empty_reply` and saves no message.
- [ ] The replacement made when a reply is saved keeps the waiting task's `input_through_position` and `accepted_by_operation_id`, and its input includes the reply.
- [ ] A conversation over the input limits sends the newest whole messages, oldest first, after the omission note, and the transfer manifest lists them and each note sent, and never changes after dispatch.
- [ ] A researcher message over the operation's `max_input_bytes` is rejected with `input_too_large` and saves nothing.
- [ ] A reply that passes `max_output_bytes` is interrupted, keeps its text up to the limit at a whole code point and fails with `output_limit_exceeded`.
- [ ] At `max_pending_tasks`, a new message is rejected with `pending_limit_reached` and saves nothing, while a message that coalesces is accepted.
- [ ] A permit refused with `permit_expired` requeues the task, whose second attempt then runs, and a second refusal fails it with `permit_expired`; when the conversation already has a not-started task, the refused task is cancelled instead and the conversation keeps one not-started task.
- [ ] The new ADR is in `docs/adr/index.md`, and ADR-0011, ADR-0028 and ADR-0037 carry the replacement link in each section it changes.
- [ ] `dispatch_permitted_at` is committed before `provider_dispatch` is posted and cleared by every not-dispatched result, and a crash between that commit and the send leaves the attempt with its value.
- [ ] Each task requests the slug of the first entry whose `visibility` is `list` in the list main reported, and records it in `requested_model`, also when an earlier entry is hidden; while the list has no such entry, a task fails with `provider_unavailable` without a dispatch permit or a work unit; and `model_list_refresh` makes main read the list again and report it, or report the list it holds when the read fails.
- [ ] A final attempt row never changes except for its token fields, and a terminal task never changes.
- [ ] Every task change advances the task's `state_revision` and its conversation's `revision` by one, and a task records its project's document language at acceptance, and none in a project in setup.
- [ ] Every state change and database rule is covered by automated tests, and a general inference limit already changed from its seeded revision is preserved by the migration.
