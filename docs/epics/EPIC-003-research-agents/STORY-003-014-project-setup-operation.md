## Acceptance criteria

- [ ] A valid proposal waits and a second replaces it.
- [ ] An unknown language, an overlong title or two calls in one reply leave an invalid proposal with its reason, reported in the next task with that reason's note at the proposal's place; two calls store the first call's values, and a call failing several checks stores the first reason in the stated order.
- [ ] Each proposal state gives the next task its exact note, and a note whose place falls among omitted messages is not sent.
- [ ] A complete tool call in an attempt that is then stopped, ends by a limit or becomes uncertain stores no proposal.
- [ ] A proposal's timeline revision moves from 1 to 2 when it is replaced, rejected or confirmed.
- [ ] After confirmation, new messages are saved and create no setup task.
- [ ] A reply with only the proposal and no text completes its task, saves no message and records the proposal with its `task_id`.
- [ ] A reply with no text and only a call outside the permitted tools or their schemas fails with `empty_reply`.
- [ ] When the pending limit is reached, the message is rejected and nothing is saved.
- [ ] Confirming a replaced proposal is rejected with `proposal_not_waiting` and confirming during a running reply with `setup_reply_active`; rejecting a proposal that is no longer waiting fails with `proposal_not_waiting`; confirming twice returns the same result.
