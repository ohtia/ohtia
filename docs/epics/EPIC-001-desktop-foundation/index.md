# EPIC-001 — Desktop foundation

- [EPIC-001 — Desktop foundation](epic.md) - Deliver a safe runnable desktop, reproducible native contribution environments and immutable build/release infrastructure with artifact-bound native coverage.

## Stories

- [STORY-001-001 — Qualify the desktop target and delivery contracts](STORY-001-001-qualify-the-desktop-target-and-delivery-contracts.md) - Define reviewed required/optional target tooling, provisional delivery mechanisms and one numeric resource contract without waiting for native probe execution.
- [STORY-001-002 — Establish the locked workspace and developer toolchain](STORY-001-002-establish-the-locked-workspace-and-developer-toolchain.md) - Provide working package boundaries and isolated, frozen JavaScript and Python tooling.
- [STORY-001-003 — Define and verify the bounded application port](STORY-001-003-define-and-verify-the-bounded-application-port.md) - Provide versioned runtime-validated IPC operations and error contracts for the foundation.
- [STORY-001-004 — Run the isolated desktop and supervised data service](STORY-001-004-run-the-isolated-desktop-and-supervised-data-service.md) - Launch a minimal graphical Electron application with a single broker, fixed-home bootstrap and a supervised utility process.
- [STORY-001-005 — Persist a minimal command with verified migration recovery](STORY-001-005-persist-a-minimal-command-with-verified-migration-recovery.md) - Demonstrate file-backed durability, exclusive migrations and verified checkpoint recovery through the real desktop path.
- [STORY-001-006 — Implement bounded diagnostics without private content](STORY-001-006-implement-bounded-diagnostics-without-private-content.md) - Emit validated content-free diagnostics through one bounded broker-owned writer.
- [STORY-001-007 — Enforce shared verification and coverage gates](STORY-001-007-enforce-shared-verification-and-coverage-gates.md) - Run the same meaningful types, lint, format, test, coverage and build checks locally and in CI.
- [STORY-001-008 — Provide the reproducible sandboxed Linux E2E environment](STORY-001-008-provide-the-reproducible-sandboxed-linux-e2e-environment.md) - Reproduce real Electron tests in an immutable Linux environment with active sandboxes.
- [STORY-001-009 — Make Linux contribution setup reproducible](STORY-001-009-make-linux-contribution-setup-reproducible.md) - Enable a new Linux contributor to install, diagnose, run and verify Ohtia from a clean checkout.
- [STORY-001-010 — Make Windows contribution setup reproducible](STORY-001-010-make-windows-contribution-setup-reproducible.md) - Enable a new Windows contributor to install, diagnose, run and verify Ohtia through a native supported path.
- [STORY-001-011 — Make macOS contribution setup reproducible](STORY-001-011-make-macos-contribution-setup-reproducible.md) - Enable a new macOS contributor to install, diagnose, run and verify Ohtia on required Apple Silicon, with independently qualified optional Intel support.
- [STORY-001-012 — Build and smoke-test native quality artifacts](STORY-001-012-build-and-smoke-test-native-quality-artifacts.md) - Produce isolated, identifiable quality packages and complete native smoke evidence for PRs and integrated source.
- [STORY-001-013 — Qualify signed installation and update mechanisms](STORY-001-013-qualify-signed-installation-and-update-mechanisms.md) - Deliver common signing/update foundations and Linux qualification with every native cell bound to its exact final package.
- [STORY-001-014 — Capture and assemble reviewed user change notes](STORY-001-014-capture-and-assemble-reviewed-user-change-notes.md) - Collect PR impact statements and assemble traceable channel-specific editorial release notes.
- [STORY-001-015 — Prepare immutable candidates through trusted authority](STORY-001-015-prepare-immutable-candidates-through-trusted-authority.md) - Reserve versions and assemble retained candidates with exact package identities, complete native-cell assignments and explicit platform capabilities.
- [STORY-001-016 — Promote and reconcile exact release artifacts](STORY-001-016-promote-and-reconcile-exact-release-artifacts.md) - Qualify exact-byte Linux publication from admitted package and native-cell evidence while denying unqualified platform distribution.
- [STORY-001-017 — Verify the integrated foundation and contributor journeys](STORY-001-017-verify-the-integrated-foundation-and-contributor-journeys.md) - Verify integrated foundation and contributor journeys, Linux delivery and exact package identity across assigned native cells and promotion.
- [STORY-001-018 — Qualify the native foundation targets](STORY-001-018-qualify-the-native-foundation-targets.md) - Prove frozen workspace installation and native runtime, addon, filesystem and delivery-mechanism feasibility on all required targets.
- [STORY-001-019 — Qualify signed macOS distribution](STORY-001-019-qualify-signed-macos-distribution.md) - Qualify Developer ID, notarized DMG/ZIP delivery and native signed installation on macOS 26/27 Apple Silicon.
- [STORY-001-020 — Qualify signed Windows distribution](STORY-001-020-qualify-signed-windows-distribution.md) - Qualify an eligible Authenticode publisher facility and signed native Windows 11 x86-64 installation.
- [STORY-001-021 — Qualify KDE Plasma as a required Linux desktop](STORY-001-021-qualify-kde-plasma-as-a-required-linux-desktop.md) - Qualify KDE Plasma 6 on Wayland as a required Linux desktop with GNOME parity on every supported distribution and CPU, with one identifier per native cell.
- [STORY-001-022 — Remove the Scaleway signing service](STORY-001-022-remove-the-scaleway-signing-service.md) - Delete the complete Scaleway signing service, its tooling, tests and documentation, keeping the ARM qualification facilities.
- [STORY-001-023 — Take the application version from the root manifest](STORY-001-023-take-the-application-version-from-the-root-manifest.md) - Derive every package version, About and the data store release from the root package.json version.
- [STORY-001-024 — Prepare a release without publishing it](STORY-001-024-prepare-a-release-without-publishing-it.md) - Add the manual workflow that reserves a version, builds its packages and stores them with attestations in an unpublished GitHub Release.
- [STORY-001-025 — Sign RPM packages in the protected environment](STORY-001-025-sign-rpm-packages-in-the-protected-environment.md) - Sign and verify RPM packages with the maintainer's OpenPGP subkey in the protected release-signing environment and document its custody.
- [STORY-001-026 — Write the first release notes into the unpublished release](STORY-001-026-write-the-first-release-notes-into-the-unpublished-release.md) - Assemble the first release-notes text from the included pull requests' ohtia-note blocks and write it as the unpublished release body.
- [STORY-001-027 — Register the Ohtia repository from installed packages](STORY-001-027-register-the-ohtia-repository-from-installed-packages.md) - Make each DEB and RPM install the Ohtia repository entry and public key so the system delivers later updates.
- [STORY-001-028 — Publish a prepared release](STORY-001-028-publish-a-prepared-release.md) - Add the manual workflow that publishes a prepared unpublished release without rebuilding, creates the version tag and records the notes digest.
- [STORY-001-029 — Publish signed Ubuntu and Debian repositories](STORY-001-029-publish-signed-ubuntu-and-debian-repositories.md) - Generate signed apt repositories for Ubuntu and Debian on R2, in the test zone at preparation and the stable zone at publication.
- [STORY-001-030 — Publish the signed Fedora repository](STORY-001-030-publish-the-signed-fedora-repository.md) - Generate the signed dnf repository for Fedora on R2, in the test zone at preparation and the stable zone at publication.
- [STORY-001-031 — Check for a newer version on startup](STORY-001-031-check-for-a-newer-version-on-startup.md) - Check GitHub for a newer published version on startup behind a default-enabled setting, without downloading anything.
- [STORY-001-032 — Show the update notice](STORY-001-032-show-the-update-notice.md) - Show a quiet title-bar button and a dialog that tells the researcher a newer version exists and how to get it on their system.
- [STORY-001-033 — Qualify repository delivery on one Linux cell](STORY-001-033-qualify-repository-delivery-on-one-linux-cell.md) - Prove on Ubuntu 26.04 x86-64 GNOME that a prepared version installs and the next arrives through the test repository with data intact.
- [STORY-001-034 — Qualify refusal of altered and wrongly signed packages](STORY-001-034-qualify-refusal-of-altered-and-wrongly-signed-packages.md) - Prove that the package manager refuses altered packages and invalid signatures and leaves the installed version working.
- [STORY-001-035 — Extend repository qualification to the x86-64 cells](STORY-001-035-extend-repository-qualification-to-the-x86-64-cells.md) - Run the repository qualification on the remaining x86-64 Linux cells, complete on GNOME and short on KDE.
- [STORY-001-036 — Extend repository qualification to the ARM64 cells](STORY-001-036-extend-repository-qualification-to-the-arm64-cells.md) - Run the repository qualification on the six ARM64 Linux cells, with Fedora and Debian on authorized ephemeral guests.
- [STORY-001-037 — Deliver the release security inventory](STORY-001-037-deliver-the-release-security-inventory.md) - Deliver the security inventory for the release boundary and release output R37 to the remaining EPIC stories.
- [STORY-001-038 — Withdraw a published release](STORY-001-038-withdraw-a-published-release.md) - Add the manual workflow that stops offering a published version without reusing its number or downgrading installed systems.
