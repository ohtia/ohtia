# Content-free broker diagnostics

## Ownership and event inventory

[ADR-0013](adr/adr-0013-private-content-free-structured-logging.md) owns the complete local file contract and OpenTelemetry mapping. [STORY-001-006](epics/EPIC-001-desktop-foundation/STORY-001-006-implement-bounded-diagnostics-without-private-content.md) implements that boundary after the [application port](application-port.md), [isolated runtime](desktop-runtime.md) and [durable store](storage.md). PRIN-004, PRIN-006, PRIN-007 and PRIN-013 require authentic artifact identity, honest uncertainty and protection of durable research when logging fails.

The [portable catalog and decoders](../packages/contracts/src/diagnostics.ts) are the executable event inventory. Each event fixes component, operation, outcome, severity and permitted error codes. Broker events cover application startup/shutdown/fatal failure, service readiness/unavailability and rejected port admission. Data-service events cover storage opening/failure/checkpoint restoration and appearance replacement success/failure/uncertainty. Actual event time is optional; observed time is assigned by the broker. Broker-owned UUID correlations identify dispatched appearance requests without retaining renderer identifiers. No current event permits task/attempt IDs: the foundation has no task execution surface that needs them. Extending that scope requires catalog and privacy verification together.

The utility submits a private generation-bound diagnostic envelope to its supervisor. The supervisor validates its exact shape and permits only data-service events from its current live child. Child-provided resources, observed time, severity, correlation, entity identifiers and metadata bags are refused. The broker constructs resource identity from the running artifact's declared version. It reports invalid inputs through a saturating rejection counter without retaining their payload. Expected appearance errors are mapped only from validated result codes; thrown exceptions never supply diagnostic fields.

JavaScript stdout/stderr capture is suppressed in the main and utility entries before runtime work; Automatic stream output is discarded; Node may format console arguments before the suppressed write, so this does not claim that custom console formatters never run. Runtime failures become fixed codes or controlled service exit. The development launcher ignores native stdout/stderr, the utility uses ignored stdio and its environment is restricted. The dependency inventory introduces no analytics SDK, tracing exporter or crash reporter. Browser resources have no network capability. These boundaries do not claim to suppress OS crash facilities outside Ohtia's control. No diagnostic content is transmitted automatically.

## Files, admission and operations

The [writer](../packages/main/src/diagnostic-writer.ts) receives only the admitted canonical research root. The broker verifies the isolated profile's stable sentinels and [data-directory admission](../packages/main/src/locator.ts) before log I/O. An invalid locator leaves graphical bootstrap diagnostics without a fallback log directory. Workers have no log file handles. The existing native broker lock supplies cross-process ownership; the writer also refuses a second instance for the same directory inside one process.

The ADR owns the five-file/5-MiB retention policy. The writer validates a record before enqueuing its encoded bytes; its additional fixed limits are 8,192 bytes per record, 64 pending operations and 64 scanned records per read page. The present closed vocabulary encodes only ASCII records, including versions, UUIDs and timestamps. Multibyte untrusted input is refused, while Unicode native paths are exercised separately. Startup and read buffers never exceed one retained file. Append, rotation, startup repair, reads and deletion share one bounded queue. DEBUG is disabled by default and does not change the allowlist.

Startup removes extra numeric managed archive names, reduces oversized managed files to a complete line within the bound and removes incomplete final lines. Unrelated filenames are untouched. Regular-file, canonical-path, owner, device/inode and single-link checks refuse aliases and hardlinks before content access. The account owner receives mode 0700 for the directory and 0600 for files on POSIX. Windows uses an asynchronous fixed native PowerShell ACL operation with a path passed as environment data; it removes inherited and other explicit rules, grants only the current SID full control and verifies the resulting protected ACL. A missing/denied permission tool makes logging unavailable and latches the failure until explicit reinitialization. Closing the writer cancels its active permission helper and discards queued work. Account-equivalent hostile filesystem replacement and forensic erasure are outside the local-log guarantee.

`initializeLogs`, `append`, `read(slot, offset)`, `deleteLogs(confirmed)`, `catalog`, `status` and `close` are broker-internal interfaces. Slots are fixed integers for active/archive names; offsets are bounded byte positions at line boundaries. Reads return copied supported records and invalid/unsupported counters, never raw lines or paths. Deletion requires explicit confirmation, reports the number actually removed on partial failure and recreates the active file after successful cleanup. These operations expose no new renderer IPC or export capability; the later Settings viewer will consume named admitted operations through its own reviewed port contract.

Write, rotation, permission and deletion exceptions become controlled `unavailable` results. Capacity rejection is `busy`; invalid records, oversized records, missing confirmation and closed writers have separate statuses. Logging does not gate storage transactions or save acknowledgements. Failure never causes recursive logging or output of an exception. A subsequent admitted operation reconciles incomplete files before further append. Diagnostics are operational records rather than crash-durable research receipts; no file synchronization or physical power-loss guarantee is inferred from successful append.
