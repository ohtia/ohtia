Settings, shortcuts, zoom and application-menu controls derive availability from that registry. A missing handler remains unavailable with its translated reason.

It registers `panels.explorer`, `panels.documents`, `panels.chat`, `document.focus` and `layout.reset` while mounted, and removes those handlers on disposal. Do not register those IDs a second time. Layout initialization and unresolved saves disable persistent actions; narrow selection and focus mode remain in memory. Dialog and IME availability is rechecked at invocation.

Keep `onWorkspaceChange` stable for the mounted controller's lifetime; replacing it intentionally replaces that controller. The optional `available` input defaults to true for standalone chrome. This first-run surface admits no manuscript or project content. `zoom`, when supplied, is the window's confirmed effective percentage. Its indicator invokes `zoom.reset`; an absent value or 100 hides it. These inputs grant no preference or native-window authority.

## Separator component

Each `WorkspaceSplitter` presents the controller's adjacent pair, range and effective widths. Its anatomy is a four-pixel slot, a centered keyboard/pointer target, a line and a hover/focus grip. Canonical tokens determine line, target, guard, grip, focus and typography. Panel content padding reserves the target's overlap inside its neighbors without changing allocated widths. Footer controls retain the specified footer padding and reserve any additional separator guard at their trailing edge. Rail controls reserve the canonical focus clearance at the window edge; their outer ring extends into the neighboring panel's empty guard above its background, preserving both rail width and target size. At rest the decorative line is subtle; hover/focus strengthens it and shows the grip; dragging uses primary content color; minimum states use a directional cursor and translated explanation.

The separator exposes vertical orientation, both controlled panel IDs, its pair name, left-panel minimum/current/maximum and a value description naming both widths. Arrow keys resize by 16 CSS px, Shift by 64, and Home/End use neighbor-constrained extrema. Enter and double-click reset only the pair using the existing controller oracle. This deliberately differs from the APG Enter collapse gesture: panel toggles own hiding, so a separator key never hides content. Per-panel reduce/increase buttons provide a non-drag alternative and disappear with a single visible panel.

Only the initiating primary pointer is captured. Successful release commits once. Escape, pointer cancellation, lost capture, focus loss, viewport/visibility changes and disposal restore starting widths and release pointer/cursor/selection ownership. Resize never creates a research action. The chrome performs no width transition during dragging; reduced motion therefore introduces no panel animation.
