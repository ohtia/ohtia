# Semantic renderer primitives

## Ownership and use

Import the components and types through `@ohtia/renderer`. The [design foundations](design-foundations.md) own the generated tokens, local fonts, icons and branding; `foundation.css` includes the primitive styles in both the desktop and catalog. Components accept translated strings, content and callbacks from their consumer. They never translate arbitrary provider prose, save preferences, contact providers, confirm knowledge or infer permission from a success message. This preserves researcher authorship and the distinction between evidence, inference and confirmation (PRIN-002, PRIN-005 and PRIN-016 in the [product definition](product-definition.md#product-principles)).

Supply stable, unique field, tab, menu-item and row identifiers. Retain component identity across locale/theme changes to preserve input and focus. The consumer owns domain capabilities, operation identity, validation errors, sorting, pagination and any asynchronous effects. Text is rendered as React text; these controls accept no HTML strings. `ReactNode` slots are for trusted application composition, not untrusted markup.

All controls support native hover, focus and active behavior. Labels wrap and controls grow within available width. Pointer targets use `component.target.minimum` and `component.target.coarse`; focus uses `focus.width` and `focus.offset`. Styling uses checked semantic colors and canonical shape/spacing tokens. There are no ordinary animation timers or decorative loading loops. Forced colors retain labels, borders and focus with system colors. A component's supported states below describe presentation, never proof that a durable task completed.

## Actions and fields

- `Button`: text action plus optional visible explanation; `primary`, `secondary`, `quiet` and `destructive` variants. `label` stays visible while `loadingLabel` supplies the loading explanation. `disabledReason` keeps the button focusable and prevents dispatch. `onPress` is the only action callback. Primary uses `action.primary.*`, destructive uses `danger.*`, secondary uses `border.control`, and quiet is underlined. Loading/unavailable controls use the neutral inactive treatment. A persistent polite live region announces transitions into loading without changing focus. Use a verb and object as the label. `ariaKeyShortcuts` supplies the registry-derived accessibility shortcut annotation without registering another keyboard listener.
- `IconButton`: named button with decorative `icon`, a hover/focus tooltip and the same loading/unavailable contract. `label` is the full accessible name; indispensable information also belongs in visible surrounding content. Use a local `LucideGlyph` as the icon when applicable.
- `Link`: always underlined, with `href` and content. Only HTTP(S), mail and fragment destinations are admitted; an inadmissible destination has no active `href`. Supply `externalLabel` for external destinations. Navigation does not use menu items or action buttons.
- `TextField`: visible `label`, controlled `value`, optional `help`, visible corrective `error` and optional `disabledReason`. `onChange` preserves the complete input, including composition. `onValidate` runs on blur, deferred until composition ends when blur happens mid-composition; it never runs while typing. Consumers validate again on submission. Errors expose `aria-invalid` and descriptions; they do not replace input or move focus. Unavailable fields stay focusable and read-only.
- `Selector`: visible label, native controlled select, translated `{value, label}` options, optional descriptions/error/unavailable explanation and `onChange`. Unavailability uses `aria-disabled` and guards the callback while retaining focus; the controlled value remains owned by the consumer. Searchable comboboxes are outside this API.
- `Choice`: labeled native checkbox/radio or immediate-setting switch. Supply `kind`, `checked`, `onChange`, descriptions and optional unavailable explanation. Radios share a consumer-supplied `name` inside a labeled fieldset. A switch represents an immediately applied setting. Inactive controls retain their labels and block callback dispatch.
- `Form`: a native form with `noValidate`, controlled `onSubmit` and trusted children. Enter during IME composition does not submit. Supply a native submit button. `ErrorSummary` remains mounted for the form lifetime and receives a title, `{fieldId, message}` errors and a submission counter. Pass an empty array when there are no errors; the component then renders no alert. On a new failed submission it focuses the linked summary, and each link focuses its field. Keep errors visible until corrected; do not increment the counter for passive snapshots or locale changes.

Fields stack their label, control and descriptions with `space.2` and constrain themselves to the available width. Their surface is `surface.page`, text is `content.primary`, border is `border.control`, and field errors use `attention.*`. No fixed text width or truncation is applied.

`useFieldDraft(initial)` supplies `value`, `edit`, `capture` and `acknowledge`. Capture the value/revision before invoking the consumer's asynchronous operation. Call `acknowledge(captured)` only for the exact confirmed receipt; it clears only an unchanged edit revision. Newer edits, including A→B→A, survive a late acknowledgement. After disposal acknowledgements return false. The hook does not dispatch, retry or decide whether a response is authoritative.

## Tabs and action layers

`Tabs` receives a label, ordered `{id, label, content, closeLabel?}` items, controlled `selected`, `onSelect` and optional `onClose`. Arrows and Home/End move focus; native Enter/Space activation invokes selection. Delete requests closing only a closable item. Each close button is a sibling of its tab. Inactive panels are hidden from focus and the accessibility tree while their content remains mounted. Only the tab row scrolls horizontally. The consumer owns closure and replacement selection. Optional `selectedTabRef` exposes the selected button through a consumer-owned React ref; pass it as a modal's `returnFocusRef` when closing the modal can remove its original trigger in the same update. If the focused tab/close control disappears, the primitive restores focus to the valid selected tab unless focus has already moved to another surface. Close buttons are additional tablist descendants and ordinary Tab stops, an intentional extension of the APG tablist pattern that keeps close controls outside the tab buttons; workspace-specific close/save decisions belong to the [workspace controller](workspace-layout.md#presentation-integration).

`ActionMenu` receives a label and ordered `{id, label, onPress, disabledReason?}` actions. Its trigger exposes expanded/menu semantics. Opening focuses the first action; arrows wrap, Home/End move to the boundaries, Enter/Space activate, Escape closes and restores the trigger, and Tab leaves the menu. Inactive items remain inspectable with their explanation and never invoke the callback. `contextual` also enables right-click, the ContextMenu key and Shift+F10 within its trusted children. The visible button remains the pointer/keyboard alternative. Menus contain actions only. Selection closes before dispatch so a callback opening a dialog captures the correct trigger.

`Dialog` receives controlled `open`, `title`, `closeLabel`, content and `onClose`. It uses native `showModal`, background inertness and focus containment. The close button and Escape request closure through the callback; changing `open` actually closes it. Cleanup restores a still-connected trigger, or the optional same-document `returnFocusRef` when that trigger is gone or cannot receive focus (for example, inside a hidden panel). `Confirmation` accepts the same fallback. Document listeners and a scoped mutation observer retain containment when focused content disappears; unexpected native closure while the controlled `open` remains true is resynchronized. Only one modal is admitted: a second open request invokes that dialog's `onClose` instead of stacking modals. `Confirmation` supplies consequences, cancellation/confirmation labels and callbacks, initially focuses the safe cancellation button and guards confirmation with an optional visible `disabledReason`. Titles name the action and object; consequences describe the affected scope. Never treat opening or dismissing a confirmation as researcher approval.

`Tooltip` wraps one element accepting `aria-describedby`; it merges its description without replacing the trigger's existing descriptions. It opens on hover/focus, remains while the pointer or focus is inside, and dismisses with Escape without reopening until the hover/focus interaction ends. Its content is optional plain text, with no interactive controls or indispensable information. `Popover` has a named disclosure button and a focusable supplementary region with explicit close control; it closes on Escape, outside pointer activation or focus leaving. Escape/explicit close restore the trigger. It remains open while inspected and has no timeout.

A dialog may supply trusted `titleContent`, `headingLevel`, `className` and `closeContent` slots. Custom `titleContent` replaces the plain heading and must convey the dialog identity; `closeLabel` still names an icon-only close button. With `bodyClassName`, the primitive places the Close control, `headingPrefix`, its named heading and children inside the scrollable body, followed by the trusted `footer`. The primitive uses a generic header group; About and Help supply generic groups through the footer slot so these dialogs do not introduce page-level landmarks. About uses those slots for its decorative illustration, H1 branding and separate Close footer while preserving the same native modal and disposal behavior.

A tab-to-dialog closure composes `Tabs selectedTabRef={selectedTab}` with `Dialog returnFocusRef={selectedTab}` (or `Confirmation`), where `selectedTab` is `useRef<HTMLButtonElement>(null)`. The consumer selects a valid remaining tab while closing/removing the old one; the same committed update refreshes the ref before modal cleanup. Ref cleanup on disposal prevents restoring to an unmounted surface.

Layers measure their trigger and viewport through CSSOM, constrain their dimensions, reposition on scrolling, resizing and observed content changes, and remove listeners/observers on disposal. Tooltips use `component.tooltip.max-width`, menus/popovers use `component.menu.max-width`, and dialogs use `component.dialog.max-width` with window margins and internal scrolling. The consumer must not place fixed layers inside a transformed containing block. Native dialog top-layer behavior makes the background inert; a dialog-local Tab loop keeps sequential focus inside its visible enabled controls.

## Outcomes, collections and regions

`StateLabel` combines a visible shape and translated label for `requested`, `accepted`, `uncertain`, `failed`, `confirmed`, `pending`, `rejected` and `review-required`. No phase is encoded by color alone. `OperationStatus` receives the current `operationId` and an optional event containing that identity, a nonnegative monotonic `revision`, phase, translated label and `source` (`snapshot` or `response`). Old identities and revisions are ignored. Snapshots update inspectable presentation silently. Within a mounted status region, current responses announce each identity/revision/phase once, including distinct outcomes with identical translated labels and A→B→A scope changes; failures/rejections use an alert, other significant outcomes use polite status. Neither region takes focus. Deduplication lasts for the component lifetime; after a remount, retained outcomes must be supplied as `snapshot`, and only newly received responses use `response`. Consumers must supply a new operation identity for a new attempt and trustworthy structured events; presentation does not authorize an action or certify research/durable effects.

`Notice` is a persistent inline section containing a shape, title, trusted content and optional action. It supports `attention` and `danger` tones using the corresponding semantic pairs. Use it for inspectable failure/recovery information; use `OperationStatus` for deduplicated live announcements. A notice's tone alone does not confer an alert role.

Mount one `ToastRegion` at the application root. It receives one optional `{id, label}` slot, `dismissLabel` and `onDismiss(id)`, so replacing the slot cannot create a stack. There is no expiry timer or focus movement. Errors must also have a durable inline location. Consumers retain operation ownership and must ignore obsolete asynchronous toast callbacks before changing this slot.

`DataTable` receives a label, column definitions `{id, label, numeric?}`, rows `{id, heading, cells}`, optional controlled sort `{column, direction, label}` and `onSort`, and optional explicit `more` action. It exposes a caption, column/row headers, `aria-sort`, locally scrollable labeled table region, sticky headers inside a viewport-bounded scroll region and right-aligned numeric cells. Scroll containers reserve the complete focus outline and offset, including during horizontal navigation. Table scroll padding also follows the measured header height, and focused body controls stay below it; overlaid menus/popovers retain their independent focus positioning. `compact` renders the same content as a list with labeled fields. Consumers select compact presentation from available width and supply sorted rows and explicit pagination/batch actions; scrolling never requests another batch. Table cells are trusted React content.

`Skeleton` marks its named group busy and exposes a static placeholder. `Progress` labels a native progress element with the current phase and optional measured `value`/`max`; absent quantity exposes a static indeterminate progressbar with its phase instead of a native looping animation. The consumer supplies valid finite quantities and does not announce animation frames. `Panel` is a labeled nonmodal section with a focusable heading; `hidden` preserves mounted content while removing its focus/tree presence. `Separator` is a static horizontal/vertical separator; it has no resize authority. Interactive window splitting belongs to the workspace controller.

## Named-command surfaces

`CommandSurfaces` composes the [named presentation command contract](application-port.md#named-presentation-commands), localized entry buttons and the local Help/About dialogs. It accepts the named command bridge, current locale, controlled decoration mode, manuscript visibility and optional feature-handler registration callback. Keep the component mounted across locale and appearance changes. Async metadata and link results are bound to the current dialog incarnation; copy feedback also carries a locale epoch. A locale change preserves a pending metadata read and discards feedback for text copied in an older locale. A dismissed dialog is never reopened by its old callback.

`AboutDialog` and `HelpDialog` also accept controlled props for isolated presentation. About receives the running metadata, bundled copyright/license/notices, copy phase and callbacks. `decoration` defaults to static; hidden mode and a visible manuscript omit the illustration and its layout space while retaining the glasses, name and metadata. Animated mode still uses this static About asset. Copy status remains neutral, failures stay inline, the notices disclosure exposes a named, focusable list with bounded scrolling, and both close routes restore the trigger through `Dialog`. The body retains a minimum reading area; when the viewport cannot accommodate both that area and the dialog chrome, the dialog itself also scrolls so focused controls remain fully visible. Help uses the shared capability message, one paragraph per Settings group, the registry-backed shortcuts action and the same broker-authorized project links. These surfaces start no inference and load no remote content.

## Isolated catalog and verification

```bash
python3 scripts/workspace.py run catalog:build
```

The independent output is `artifacts/semantic-catalog`, never a product package or independently distributed design-system product. The admitted `preview` command described in [Locked developer workspace](developer-workspace.md#common-commands) serves that built artifact on loopback with the desktop's restrictive CSP. All actions are synthetic; nothing is saved or sent to a provider.
